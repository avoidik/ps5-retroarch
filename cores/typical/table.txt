# Typical cores: upstream source built as is with the shared flags in
# ../_common.sh, then verified and staged. Their whole recipe is a declaration.
# A core needing anything more - a source patch, a build assertion, an .info
# fixup - gets a script in ../patched/ instead. Cores kept close to the scripts
# in ps5-payload-dev/websrv live in ../websrv/.
#
# Pipe-separated. Blank lines and #-comments are ignored. Trailing fields may be
# left empty.
#
#   name | repo | make_dir | makefile | make args | extra CC/CXX defines | branch
#
#   name        also names the .so and the .info (<name>_libretro.*)
#   repo        GitHub owner/repo, or gitlab.com/owner/repo
#   make_dir    directory holding the libretro makefile, relative to the source
#               root; empty means the root itself
#   makefile    empty means Makefile
#   make args   later arguments win, so these can override _common.sh's own
#               (platform=unix, CC, ...) and the makefile's defaults
#   branch      empty means master; a commit hash pins that exact commit
#
# Add a core by adding a row. Nothing else needs to change - build-core.sh and
# the release workflow (via ../_matrix.py) both read this file.
